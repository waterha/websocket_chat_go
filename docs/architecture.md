# 聊天项目职责边界

本次重构只移动实现与显式传递依赖，保留 REST/WebSocket 协议、数据模型、SQL、事务范围、权限检查顺序、现有界面及样式覆盖顺序。

## 前端

`web/src/main.js` 是应用组合入口，保留会话选择、消息缓存/同步、会话级生命周期以及跨模块流程的协调。功能模块不导入入口，也不接收整个应用上下文；仅通过具名参数接收需要的 ref、回调和会话版本读取函数。

| 模块 | 拥有的职责 | 外部协作 |
| --- | --- | --- |
| `composables/use-profile.js` | 个人资料编辑、头像裁剪与上传/移除、密码修改 | 当前用户、刷新、错误展示、图片转换、会话版本 |
| `composables/use-contacts.js` | 好友备注/删除、黑名单与联系人面板状态 | 好友列表、设置菜单、错误展示、会话版本 |
| `composables/use-announcements.js` | 公告列表、编辑面板与增删改 | 活跃会话、权限计算、刷新、错误展示、会话版本 |
| `composables/use-thread-window.js` | 回复窗口、窗口分页、独立草稿与回复发送 | 活跃会话、同步、错误展示、会话版本 |
| `composables/use-history-search.js` | 当前会话历史筛选、成员搜索、分页、请求取消 | 活跃会话、成员数据、重置定位回调 |
| `composables/use-global-search.js` | 跨会话搜索面板、关键词与游标分页 | API 层 |
| `composables/use-composer-undo.js` | 富文本草稿快照、撤销/重做、光标及 IME 状态 | 编辑区、图片集合、上传状态、草稿、提及更新回调 |

消息定位由入口协调缓存、可视窗口和滚动，搜索模块无需了解缓存结构。历史重置通过回调取消旧定位；模块中的异步操作继续使用原有会话版本保护。IME 状态通过实时读取函数提供给发送/删除处理，不能传递布尔快照。资料模块拥有裁剪取消控制器及卸载清理。

`template.js` 组合 `templates/` 中的视图片段，所有片段保留同一个根模板绑定作用域；不借拆分改动 DOM 或组件层级。`style.css` 按原顺序导入 `styles/` 中完整连续的语义段，后续覆盖仍保留在后续位置。详情见 [视图模块说明](../web/src/VIEW_MODULES.md)。既有 `api`、`desktop`、消息编辑/操作等基础模块继续独立使用。

## 后端

同一个 `logic` package 内按群成员、禁言、群设置、邀请、自助入群申请、审批、好友关系、好友请求、黑名单、消息校验、发送事务与拍一拍拆分文件。没有引入新服务层或仓储接口；既有事务内公共辅助方法继续共用，不拆开事务。具体职责表见 [后端模块说明](../backend/README.md)。

## 验证与后续维护

- 前端运行 `node --test src/*.test.js`（在 `web` 目录）与 `npm run build`。既有交互测试覆盖原入口；`composables.test.js` 额外检查模块独立状态、会话版本、分页/取消、回复发送和 IME 状态交接。
- 后端运行 `go test -count=1 ./...` 与 `go build ./...`（在 `backend` 目录）。集成测试需要 `IM_TEST_DATABASE_URL`、`IM_TEST_REDIS_ADDR` 等原有测试环境配置，使用现有隔离 schema fixture。
- 新增功能状态与操作放在对应职责模块；入口只协调跨功能流程。不要传入整个根状态对象或让模块反向导入入口。
- 模板拆分须保持相邻 `v-if`/`v-else`、ref、指令与空白；样式移动必须验证最终级联顺序。
- 重构提交不应混入协议调整、数据库迁移、行为修复或界面重设计；这些需要独立变更。
