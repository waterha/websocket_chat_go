# 统一状态与桌面性能验证（2026-11-11）

## 一致的内容反馈

共享 `ContentState` 组件统一三类状态：空内容使用收件箱图形和“暂无内容”；加载使用旋转图形和“加载中…”；失败使用警示图形、“加载失败”及同样式重试按钮。上下文放在说明文字中，不丢失“群文件”“搜索结果”“联系人”等具体含义。窄侧栏使用紧凑排列；主题沿用现有颜色变量；装饰图形对读屏隐藏；状态使用 status/alert 角色；减少动态效果偏好会停止旋转动画。

接入聊天记录、历史/全局搜索、回复窗口、公告、会话/好友/成员列表、邀请/转发、收藏、群文件、群列表、通讯录与桌面本机服务启动反馈。加载/失败/空内容互斥，不再在失败后同时显示“暂无内容”。聊天记录加入真正读取状态与失败重试；分页失败保留已加载结果，群文件和通讯录显式保留失败请求的分页模式。保存/删除/入群等操作级错误不误用“重新加载列表”按钮。

## 渲染与空闲成本

- 会话/私聊/最新消息/跨会话成员姓名采用按数据变化失效的计算索引。排序时不再复制、反转完整历史；好友排序和消息姓名渲染不再反复线性查找所有会话或成员。
- 最新消息从尾部读取，不为预览复制历史。当前消息窗口反向提取所需的非话题回复行，保留升序及原分页/定位行为，不再全历史 filter 后 slice。
- 空同步页仍严格验证连续游标，但返回原历史数组，避免历史复制、会话预览重算和当前消息列表重绘。
- 输入状态时钟只在过期清理时触发必要更新，空闲时不再每秒递增响应式值。消息同步、通知与接收游标回执保留，不以关闭后台功能换性能。

专项脚本测试创建 5,000 个会话、每会话 100 条历史消息（共 500,000 条），对比会话索引建立、会话排序和 1,000 次私聊查找。本机一次独立定向运行：新方案约 24.40ms，旧等价工作约 283.74ms；在并行界面测试下也观察到约 90.88ms 对 783.11ms。只报告诊断样本，不设时间阈值、不当作 p95/FPS/整机内存承诺。确定性断言验证每个会话历史仅获取一次，100 条可见消息只读取 100 个数组元素，结果与旧逻辑一致。空同步测试验证一万条历史保留原数组身份且无效游标仍被拒绝。

复现：

```powershell
Set-Location web
node --test src/conversation-index.test.js src/realtime.test.js src/content-state.test.js
```

## 原生网络及生命周期

- 健康轮询以 64KiB 上限读完小型响应，在保留 2 秒超时的前提下复用连接。真实 httptest TCP 计数：10 次带 JSON 响应的轮询仅 1 次新连接，重复 20 轮通过。
- WebSocket 拨号前预留 ID，避免重复桥接调用发起多余握手；关闭连接可取消未完成拨号，旧拨号清理通过身份令牌保护重试。真实服务端测试验证同时重复打开仅 1 次握手，取消后 ID 可重用；取消样本约 0.00–0.01 秒，断言在 2 秒内完成而非等 10 秒拨号超时，重复 20 轮通过。
- 客户端关闭在锁内快照、锁外释放连接，避免注册表锁与读取清理争用。
- 启动器在调度 goroutine 前同步登记取消函数，关闭后禁止再次重试拉起本机服务，已取消任务不会开始初始化。
- 保持原有 Cookie/CSRF/Origin/重定向隔离、附件流式传输及 WebView 选项。没有通过关闭安全检查或消息同步获得性能收益。

原生 `go test ./... -count=1` 与 `go vet ./...` 均通过。未做实际窗口帧率、整机 CPU/RSS、冷启动总时长或 race detector 验证，不声称这些指标已量化改善。
