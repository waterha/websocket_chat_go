# websocket_chat_go

Go + PostgreSQL + Redis + Vue 的企业内部协作项目，提供网页版和基于 Wails / 系统 WebView2 的 Windows 桌面端。当前支持账号、单聊/群聊、好友备注与黑名单、群治理（群昵称、禁言、解散、入群审批）、同事通讯录、消息表情回应、输入中状态、WebSocket、离线存储、消息漫游、接收游标与已读回执；部门层级、企业管理员与多企业隔离尚未实现。

## 已实现

- 侧边栏“同事通讯录”可按姓名、账号、部门、职位搜索本服务器的其他账号，按部门筛选、分页加载并直接发起单聊，无需先添加好友。“我的工作资料”可维护本人的部门和职位（各最多 100 字，可清空）；这些字段由本人填写，不代表企业认证或管理权限。面板按需加载，不增加登录时的接口请求。
- HTTP API 与 WebSocket 共用业务逻辑；按用户/设备管理长连接，心跳、同设备重连替换、慢连接断开，最多 8 个设备/用户。
- 单聊唯一会话、最多 1000 人群聊（含创建者）；批量写入成员，按会话成员向所有在线设备推送，非成员不能读写该会话。
- 私聊从联系人直接进入；若双方尚无会话则自动创建。群聊可以只有创建者，之后由群成员按需邀请其他用户加入，并在群内保留“邀请人邀请成员进入群聊”的系统提示。群聊标题栏可打开完整成员列表，按昵称或账号搜索成员，并标注本人。
- 前端侧边栏分为“当前、好友、群聊”：当前只显示有消息的最近会话，好友显示已添加用户，群聊显示当前用户加入的全部群聊；可通过“添加”发送好友申请，并在“申请”中同意或拒绝。三个列表都可按昵称、账号或群名称即时筛选。
- 设置中可以查看并修改个人用户名和用户账号。
- 聊天标题栏支持搜索当前会话的完整历史消息：关键词不区分大小写、匹配结果高亮、分页加载，点击结果可定位原消息；仅会话成员可搜索。
- 消息、会话序号和待推送事件在 PostgreSQL 同一事务提交；`(sender_id, client_msg_id)` 幂等。每个会话内 `seq` 连续递增，不承诺跨会话全局顺序。
- 不在线的消息仍持久化；`/sync` 按升序分批补拉并返回游标。推送是低延迟提示，断线、慢消费或进程异常时以数据库补拉为准。
- 每位成员的已读位置与每台设备的接收位置分离，位置只前进不后退。接收不等于已读；已读变更推送给会话成员。
- 发送者可按消息查看其他成员的接收确认人数，明确区分“服务器已保存”“成员设备声明已接收”“用户已读”；查询失败或未确认不冒充成功。
- 服务端每 5 秒按在线设备接收游标与会话最新序号对账；未确认收齐时持续发送定向补拉提示，不依赖 outbox 已发布状态或已读状态。客户端连续处理消息后才确认，确认失败会重试；离线成员重新上线后补齐。
- Vue 客户端支持重连、定期补拉、多页漫游、已读状态与同 ID 安全重试；旧 `frontend/` 是不连服务的视觉演示。
- 图片与视频附件：先上传再发送，附件的上传者必须是发送者本人且属于同一会话；聊天窗口内直接显示图片缩略与视频播放器，可附带文字说明。图片上限 10 MB、视频上限 100 MB；附件字节存入 `MEDIA_DIR`，数据库只保存元数据与归属。
- 图片可直接粘贴或拖入输入框，并**按输入位置与文字一起组成一条消息**：输入框是富文本区，`Ctrl+V` 或拖入时图片**直接以图片本身显示在光标处**（不是占位符），可以继续在它前后打字、换行、再粘贴下一张，思路与最终效果一致；按 Enter 后整段内容作为**一条消息**发出，气泡里按你输入的顺序依次显示文字与图片。图片是整体单元，退格一次即删除整张，也可点右上角 × 移除。一条消息最多 20 段（每张图片算一段）。剪贴板图片缺少类型时按扩展名推断，仍未知则按 PNG 处理；BMP/AVIF/HEIC/TIFF 等后端不作为内联图片的类型会在浏览器内转码为 PNG，无法转码时退回为文件消息。服务端内联白名单为 PNG、JPEG、GIF、WebP（刻意不含 SVG，避免内联脚本）。
- 通用文件附件：任何类型都可作为文件发送（上限 50 MB），下载时以附件形式返回，不在应用源内渲染；聊天窗口显示文件名与下载入口。
- 跨会话全局搜索：搜索当前用户参与的全部会话，排除已撤回消息，结果标注来源会话与成员数，点击可直接定位原消息。
- 安全基础：所有写请求需要会话绑定的 CSRF 令牌；登录失败按账号限流（15 分钟 10 次，超限返回 429 与 `Retry-After`）；可修改密码，修改后自动退出其他设备上的登录。
- 会话偏好：可置顶与免打扰单个会话。置顶会话在侧边栏单独置顶显示；免打扰只抑制本机未读角标，不改变消息投递。偏好按成员保存，其他成员不可见。（归档曾实现，因不改变任何可见行为与权限，已移除。）
- 群聊治理：创建者自动成为群主，可设管理员、移除成员、转让群主；成员可自行退群。移除成员不删除其历史消息，管理员不能移除群主或其他管理员，群主必须先转让才能退群。所有治理动作都写入可漫游的系统提示。
- 群聊右侧信息区：上方为**群公告**区块、下方为**群成员列表**，两者在聊天时始终可见（不再藏在弹窗里）。点击公告区块进入公告界面可查看全部公告；群主与管理员可**新建、编辑、删除**任一公告，普通成员只读。成员列表显示在线状态并支持搜索，群主/管理员可在此邀请或管理成员。
- 成员列表按「群主、管理员、其他成员」排序并标注身份与在线状态。
- 邀请成员对话框：列表限定在固定可滚动区域内，**「邀请加入群聊」按钮始终可见**，无需滚到底部。支持按用户名或账号搜索、按首字母（A–Z）筛选并分组显示；选中项在切换筛选时保留，可「全选当前结果」或「清空已选」，按钮文案显示将邀请的人数并受 1000 人上限约束。非拉丁名字（如中文名）归入「其他」分组而非按拼音猜测字母，但仍可被搜索到。
- 消息支持引用回复、@提及成员与撤回：发送者可在 2 分钟内撤回自己的消息，群主与管理员可撤回本群任意消息；撤回保留序号并隐藏内容，**同时使附件不可下载**，历史与补拉不受影响。
- 回复组织成**对话窗口（话题串）**：点击「回复」展开该消息的专属窗口，窗口内显示全部回复并可继续回复；主界面每条消息最多显示前 3 条回复与真实回复总数，点击可进入窗口。回复的回复归入同一窗口（扁平结构），窗口与主聊天界面在布局上明确区分。
- 存储保留清理：每 5 分钟回收已发布且过期的 outbox 行与「已撤回消息」的附件字节，未发布行与正常引用的附件永不删除。
- 好友关系管理：好友列表展示仅自己可见的**好友备注**，在「联系人管理」（侧边栏“管理”）中可为好友设置备注、删除好友、加入黑名单；删除好友不影响聊天记录。黑名单内的用户无法发送好友申请、无法与你建立或继续单聊（对方发送会被服务端拒绝），可随时移出黑名单。
- 群治理扩展：成员可设置**群昵称**（群名片，仅本群可见，消息与会话内优先显示）；群主/管理员可对成员**定时禁言**（如 10 分钟）或解除，可开启**全员禁言**（仅群主与管理员可发言）；群主可**解散群聊**（历史保留、全员禁言，系统提示全员可见）；可开启**入群需审批**——普通成员的邀请会生成待审批请求，管理员在成员面板中同意或拒绝，侧边栏群聊项上显示待审批数量角标。
- 消息**表情回应**：右键消息可从常用表情中选择回应，气泡下方聚合显示表情与人数，再点一次取消；回应通过 WebSocket 实时同步给全部成员。单聊中自己发送的消息显示**已读/已送达**回执。
- 会话管理：右键会话可**置顶/取消置顶、开关消息免打扰、删除会话**（仅从自己的列表移除，收到新消息自动恢复）；对方正在输入时在输入区上方实时显示。

- 在线状态：`POST /presence` 与 `GET /conversations` 的 `online` 字段反映最近心跳窗口内是否有活动连接，仅作提示，不是投递保证。

## 本地运行

需要 Go 1.26 和 Node.js 22+。数据库和缓存由启动脚本在项目内的 `.dev/` 目录中准备，不需要提前安装 PostgreSQL 或 Redis。

**双击根目录的 `启动项目.bat`** 即可：

- 首次运行会初始化独立的 PostgreSQL 数据目录、下载便携版 Redis、安装前端依赖（不会触碰机器上已有的数据库）；
- 随后启动 PostgreSQL、Redis、后端和前端，健康检查通过后自动打开 `http://127.0.0.1:4173`；
- 已在运行的服务自动跳过，不会重复启动。

停止时双击 `停止项目.bat`，会关闭本项目的前端、后端、数据库和缓存。数据、日志和编译产物都在 `.dev/`（已被 git 忽略），删除该目录即可重置本地环境。

命令行等价用法：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1
# 只启动、不打开浏览器
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1 -NoBrowser
# 停止
powershell -ExecutionPolicy Bypass -File .\scripts\stop.ps1
```

端口读取 `.env`：前端 4173、后端 8080、PostgreSQL 5433、Redis 6379。若要使用已有的 PostgreSQL，设置 `IM_POSTGRES_BIN` 指向其 `bin` 目录；若要使用已有 Redis，设置 `IM_REDIS_DIR`。附件默认保存在项目下的 `media/`，可用 `MEDIA_DIR` 指向其他目录。

也可以手动启动依赖：

```powershell
Copy-Item .env.example .env
# 修改 .env 内 POSTGRES_PASSWORD
docker compose --env-file .env -f infra/compose.yaml up -d
```

在两个终端分别运行：

```powershell
Set-Location backend
go run ./cmd/server
```

```powershell
Set-Location web
npm ci
npm run dev
```

打开 `http://127.0.0.1:4173`。后端监听 `127.0.0.1:8080`，`GET /healthz` 检查依赖。服务在启动时读取根目录 `.env`，执行版本化迁移；已有最初版本的数据库也可升级。生产环境应由独立迁移任务执行 DDL，并关闭服务账号的 DDL 权限。

接口示例见 [backend/API.md](backend/API.md)，运行和架构说明见 [backend/README.md](backend/README.md)，数据表见 [database/README.md](database/README.md)。历史消息存储的技术比较、保留 PostgreSQL 的依据及本轮索引优化验证见 [存储调研](docs/research/2026-10-18-message-history-storage.md)。

## 群消息防漏收

即时广播不等于接收成功。消息先持久化，WebSocket 快速推送；独立对账检查每个在线设备是否确认到最新 `seq`，缺失则反复提醒按 `/sync` 补拉。客户端只确认连续序号，重复消息不重复展示；慢连接断开后重连恢复，离线成员仍保留补拉资格。即使最后一条广播丢失、没有后续消息，对账也能发现缺口。

保证的是：消息仍保留在数据库，成员继续有访问权限，数据库/网络恢复且客户端重新上线并遵循接收协议时，最终可以补齐。无法保证永久离线或不处理补拉提示的客户端收到消息，也不保证所有人同一时刻收到。接收确认与已读完全独立；当前浏览器缓存是内存，重新加载仍从数据库恢复。1000 人是群成员上限，不是已通过生产并发压测的容量承诺。

浏览器在发送前把稳定消息 ID 与原文保存在当前标签页的 `sessionStorage`：若发送结果未知，刷新同一标签页后仍可恢复原文并用同一 ID 安全重试；同步到相同消息或收到发送 ACK 后清除记录。修改原文前须先明确放弃旧确认，放弃**不代表服务器撤回消息**。退出登录会清除记录；关闭标签页、清除浏览器存储或换设备时不保证保留待确认 ID，不应据此断言发送失败。

## 当前边界

**可以多实例部署，但仍有前置条件。** 单个 dispatcher 通过数据库 advisory lock 独占消费 outbox，并同时把每条事件发布到 Redis 频道 `im:events`；所有实例订阅该频道并投给本地连接，同时用实例 ID 跳过自己已投递的事件，因此同一事件不会重复到达。审计曾实测到多实例下推送被随机瓜分（两实例各约一半、无一两边都到），该问题已修复并有跨实例回归测试。仍需注意：Redis 不持久化频道消息，订阅期间断线的实例不会补收，只能靠 5 秒 reconciler 与 `/sync` 兜底；实例 ID 默认随机生成，可用 `INSTANCE_ID` 固定以便排查。

已有：组织内的会话与群治理、图片/视频/文件附件、跨会话全局搜索、CSRF 校验、登录限流、修改密码、在线状态与保留清理。仍没有：组织/租户、细粒度 RBAC、推送通知、音视频、端到端加密、审计日志和二次验证，不应直接作为企业生产系统暴露到公网。附件未做病毒扫描与内容审查；扩容前仍需设计跨网关事件投递的监控与告警、保留策略与安全治理。
